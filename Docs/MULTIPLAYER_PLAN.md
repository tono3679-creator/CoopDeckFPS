# MULTIPLAYER_PLAN — オンライン協力の設計

> 最終目標：**最大4人の協力プレイ**（人間＋NPCで合計4人）。
> 方式：**ホスト権威型**。Netcode for GameObjects（NGO）＋ Unity Multiplayer Services（Lobby / Relay）。
> 完成版のオンライン機能は Phase 6。ただし放置せず、**Phase 2.5 で最小の2クライアント通信テスト**を行う。

---

## 1. 方針

| 項目 | 方針 |
|---|---|
| 権威 | ホスト（＝サーバー兼プレイヤー）が戦闘の正本を持つ |
| ネットワークライブラリ | Netcode for GameObjects（使用中の Unity に対応した安定版） |
| マッチング | Unity Multiplayer Services の Lobby（部屋）＋ Relay（NAT 越え） |
| 人数 | 最大4人。空き枠は NPC が埋め、途中参加の人間が NPC 枠を置き換える |
| 段階 | Phase 2.5：移動の同期のみ → Phase 6：戦闘・デッキ・コンボの同期 |

## 2. すでにコードで分離しているもの（Phase 1 時点）

ネットワーク化を見据え、最初から以下を分離している。

| 分離点 | 内容 | ネットワーク化での使い方 |
|---|---|---|
| 入力 → コマンド | 入力は `PlayerInputReader`（`CoopDeck.Input`）が読み取り、`CharacterCommands` 構造体を出力。キャラクターは `ICharacterCommandSource` 経由でコマンドを受け取る | ローカル入力・NPC の AI・ネットワーク受信を同じインターフェースで差し替える |
| 移動 | `FpsMotor` / `FpsLook`（`CoopDeck.Player`） | コマンドから決定的に移動を計算 → クライアント予測・ホスト照合に使える |
| 武器 | `WeaponState`（純 C#）＋ `HitscanWeapon`（`CoopDeck.Weapons`） | 発砲の可否・弾数をホストで検証 |
| ダメージ | `DamageInfo` / `IDamageable` / `Health`（`HealthModel`）（`CoopDeck.Combat`） | ダメージ適用はホストのみ。結果（HP）を同期 |
| イベント | 静的イベントバス `CombatEvents` | ホストで発生した結果をクライアントへ配信する起点 |
| 演出 | `CoopDeck.Effects`（エフェクトはイベントから再生） | 演出は各クライアントでローカル再生（同期しない） |
| 戦闘主体 | `ICombatActor` を人間・NPC・リモートプレイヤーで共通化 | NPC 枠を人間が置き換えても、デッキ・コンボ・援護の仕組みが同じ |

アセンブリも `Core / Combat / Input / Effects / Weapons / Player / Enemies / UI` に分かれており、将来 `CoopDeck.Networking` がこれらを参照する形で追加する（逆方向の依存は作らない）。

## 3. 権限（オーナーシップ）表

| システム | 誰がシミュレーション | 誰が検証・確定 | クライアントの扱い |
|---|---|---|---|
| プレイヤー移動 | 所有クライアント（予測） | ホスト（後から照合・補正を導入） | Phase 2.5 は所有者権威の位置同期で開始し、Phase 6 でホスト照合へ移行 |
| 視点（向き） | 所有クライアント | ホスト（妥当性チェックのみ） | 送信して他者の表示に使う |
| 射撃・命中 | 所有クライアントは発砲リクエスト＋エフェクトの即時再生 | **ホストが命中判定・ダメージを確定** | ヒットマーカーはホストの確定結果で表示（必要なら仮表示） |
| 弾数・リロード | ホスト | ホスト | 所有クライアントは予測表示 |
| HP・死亡・蘇生 | ホスト | ホスト | 結果を受信して表示 |
| デッキ・ゲージ（`DeckState`） | **ホスト** | **ホスト** | クライアントは手札・ゲージのスナップショット／差分を受信して UI 表示。スキル発動はリクエストとして送る |
| アイテム所持数 | ホスト | ホスト | 受信して表示 |
| 状態異常・属性付与 | ホスト | ホスト | 受信して表示・演出 |
| **コンボ判定** | **ホストのみ** | **ホストのみ** | 結果（コンボ種別・位置・対象）を受信して演出 |
| NPC の判断・行動 | **ホスト** | ホスト | 位置・アニメーション状態を受信 |
| 敵 AI | ホスト | ホスト | 位置・状態を受信 |
| エフェクト・SE | 各クライアントでローカル再生 | — | イベント（RPC）を受けて再生。同期しない（見た目のみ） |
| 報酬選択 | 各プレイヤーが選択 | ホストが確定 | 自分のデッキ分のみ |

## 4. 同期するデータ（システム別）

| システム | 同期データ | 頻度 |
|---|---|---|
| キャラクター | 位置、ヨー、ピッチ、速度（アニメーション用）、接地フラグ | ティックごと（目安 30Hz、補間） |
| 入力（Phase 6） | `CharacterCommands`（移動、視点、ボタン） | ティックごと、所有者 → ホスト |
| 武器 | 発砲リクエスト（時刻、照準レイ）、弾数、リロード状態 | 発砲時／変化時 |
| ダメージ | `DamageInfo` の要約（対象、量、属性、ヘッドショット、コンボ） | 発生時（イベント） |
| HP | 現在値・最大値 | 変化時 |
| デッキ | 手札各枠の `instanceId`・定義ID・ゲージ、山札・捨て札の枚数、イベント | 変化時（差分） |
| デッキ乱数 | シード（ラン開始時）＋操作列 | 開始時。決定性によりシャッフル結果を再現可能 |
| 状態異常 | 対象、属性、残り時間、付与者 | 付与・解除時 |
| コンボ | コンボID、位置、対象、協力フラグ | 発生時 |
| NPC | キャラクターと同じ＋現在の行動（演出用） | ティックごと |

## 5. NPC と人間の置き換え

- NPC は**ホスト上**で動作し、AI が `CharacterCommands` を生成する（人間と同じ経路）。
- 人間が途中参加したら、空いている NPC 枠の `ICharacterCommandSource` を「ネットワーク入力」に切り替える。
- NPC のデッキ（8枚・2枠）は置き換え時にそのまま引き継ぐか、参加者のキャラクターの初期デッキに入れ替えるかを Phase 6 で決める（初期案：参加者のキャラクターで初期化）。
- 合計人数は常に4以下。人間が抜けた場合、その枠を NPC に戻す。

### 実装済みの受け口（Phase 4、2026-11-07）

- NPC の体はプレイヤーと同じ `FpsCharacter`（移動・武器・`SkillCaster`・`DeckController`・`Health`・`Revivable`）。入力元だけが違う：人間 = `PlayerInputReader`（`ControllerKind.Human`）、NPC = `NpcController`（`ControllerKind.AI`）。`FpsCharacter.SetCommandSource` で差し替えると、デッキ・HP・装備はそのまま新しい入力元に従う（PlayMode テスト済み）。ネットワーク入力は `ControllerKind.Remote` の `ICharacterCommandSource` を足すだけ。
- ホストで一元管理するもの：NPC の思考（`NpcController`／`NpcDecisionMaker`／`NpcStateMachine`）、ダメージ（`Health`）、カード消費（`DeckState`）、コンボ判定（`ComboSystem`）、蘇生（`ReviveModel`）。クライアントは `CharacterCommands`（人間）を送り、結果（位置・HP・手札・`ComboEvents`）を受け取る。
- 指示（方針切替・集中攻撃）は `CharacterCommands.OrderTacticPressed / OrderMarkPressed` で送られ、指示を出した人の `FpsCharacter` のイベントを NPC が購読する。どのクライアントの指示かもそのまま区別できる。
- 敵の攻撃予告は `CombatEvents.ThreatRaised`（`ThreatWarning`）。NPC の回避はこれを使う（クライアントは予兆エフェクトを見る）。

## 6. 帯域の目安（4人）

| 項目 | 見積もり |
|---|---|
| キャラクター状態 | 1人あたり約 24〜32 バイト × 30Hz ≈ 1KB/s |
| 4人分（ホスト → 各クライアント） | 約 4KB/s（＋ NPC・敵） |
| 敵（例：20体） | 1体あたり約 16 バイト × 10〜20Hz ≈ 3〜6KB/s |
| イベント（ダメージ・コンボ・デッキ） | 戦闘中に変動。まとめて送信し、エフェクトは ID のみ送る |
| 合計目標 | ホストの上り **50KB/s 以下**（クライアントあたり） |

- エフェクトの詳細（粒子の位置など）は送らず、ID と位置だけ送ってローカルで再生する。
- デッキは差分送信。山札の中身はクライアントに送らない（枚数のみ）。

## 7. Phase 2.5：最小2クライアント通信テスト手順

目的：ネットワーク化の土台を早期に確認する（**移動の同期のみ**）。

### 準備

1. Netcode for GameObjects を Package Manager で追加（使用中の Unity に対応した安定版）。
2. 必要に応じて Multiplayer Play Mode パッケージを追加（Editor 内で仮想プレイヤーを起動できる）。
3. 専用シーン `Net_Smoke`（仮名）を作成し、`NetworkManager` と `UnityTransport` を配置。
4. プレイヤー Prefab に `NetworkObject` と位置同期（初期は所有者権威の Transform 同期）を追加し、`NetworkManager` に登録。
5. 簡易 UI（Host / Client ボタン、接続先 127.0.0.1）を用意。

### 実行（どちらかの方法）

- **方法A：Multiplayer Play Mode** — メイン Editor で Host、仮想プレイヤーで Client を開始。
- **方法B：Editor＋ビルド** — Windows ビルドを1つ起動して Host、Editor で Client（または逆）。

### 確認項目（2026-11-08、方法B の変形：同じ PC で Windows ビルドを 2 つ起動して検証）

- [x] Host を開始すると自分のプレイヤーが出現する
- [x] Client が参加すると、両方の画面に2人のプレイヤーが表示される
- [x] 互いの移動・向きが見える（大きな遅延・ワープがない）— 定常時は表示遅れ約 0.19 秒・位置の誤差は中央値 5 cm。参加・再接続の直後 1.5 秒だけ追いつきのずれあり（下記 7.2）
- [x] 自分の入力で他人のキャラクターが動かない（所有権が正しい）
- [x] Client の切断・再接続でエラーが出ない
- [x] 結果（使用バージョン、問題点）を本ドキュメントに追記

この段階では Lobby / Relay は使わずローカル接続でよい。Lobby / Relay は Phase 6 で導入する（Unity Cloud プロジェクトの設定が必要）。

### 7.1 実装（2026-11-08）

| 項目 | 内容 |
|---|---|
| バージョン | Unity 6000.5.4f1、Netcode for GameObjects **2.13.3**（このエディターでの登録版）、Unity Transport（依存として自動追加）。§8 の「6000.6.8f1 に更新してから導入」は、更新がユーザー指示で保留のため先に導入した。更新時に版の互換性を再確認する |
| プレイヤー | `PF_NetPlayer` = `PF_Player` の Prefab Variant ＋ `NetworkObject`・`NetworkTransform`（**所有者権威**、位置 xyz・ヨーのみ、補間あり）・`NetworkPlayer`。`PF_Player` 自体は変えていない |
| 所有者の端末 | 単独プレイと同じ経路：デバイス → `PlayerInputReader` → `CharacterCommands` → `FpsCharacter.Step`。ピッチ・接地・スプリントを `NetPose`（4 バイト、所有者が書く `NetworkVariable`）で送る |
| 他の端末のコピー | `RemoteCommandSource`（`ControllerKind.Remote`）、`FpsCharacter` を停止（シミュレーションしない・`CombatantRegistry` にも載らない）、入力を無効化、一人称リグ（カメラ・オーディオリスナー・腕と銃）を非表示、全身を表示（自分の体は影だけの設定を解除）、全身アニメは受け取った位置からの速度（`RemoteMotion`）と `NetPose` で動かす |
| シーン | `Net_Smoke`（52 m 四方の囲い・目印の柱 4 本・ロビーカメラ）。`NetworkManager`（30 Hz、接続承認で出現位置 4 か所、シーン管理なし）と `NetSmokeSession`（Host / Join / Leave の簡易パネル）。ビルドの 2 番目のシーン |
| 生成 | `NetSmokeSceneBuilder`（ブートストラップ内、単体は `CoopDeck > Setup > Build Net Smoke Scene (Phase 2.5)`）。プレハブ一覧は Netcode 既定の `Assets/DefaultNetworkPrefabs.asset` |

**手で試す方法**

```
Builds\...\CoopDeckFPS.exe -nethost                         # Host（127.0.0.1:7777 で待ち受け）
Builds\...\CoopDeckFPS.exe -netclient 127.0.0.1             # 別のウィンドウで参加
Builds\...\CoopDeckFPS.exe -nethost -netlisten 0.0.0.0      # 別の PC から参加させる（初回はファイアウォールの確認が出る）
Builds\...\CoopDeckFPS.exe -netclient 192.168.x.x           # 別の PC から Host の IP へ
```

引数なしで起動して Editor で `Net_Smoke` を開いて Play しても、左上のパネルから Host / Join できる。`-port` / `-ip` は Unity Transport 自身が読む引数なので使わず `-netport` を使う。

**無人テスト**（`-netauto 秒 -netout パス [-netreconnect 秒]`）：自分のプレイヤーを `NetSmokeWalker` が `CharacterCommands` で歩かせ（円を描く・スプリント・横移動・ジャンプ、決まった時間に相手の方を向く）、サーバー時刻つきの自分と相手の位置、所有権の状態（1 秒ごと）、接続・切断、RTT、エラー・警告、スクリーンショット 2 枚を JSON に書いて終了する。

### 7.2 結果（2026-11-08、ROG Ally X 1 台で Release ビルドを 2 つ、ループバック）

Host 32 秒・Client 27 秒（Client は 14 秒で切断し 1.5 秒後に再参加）。自分の位置と、相手の端末に見えた位置をサーバー時刻で突き合わせた。

| 項目 | Host から見た Client | Client から見た Host |
|---|---|---|
| 表示の遅れ（誤差が最小になるずらし幅） | 0.185 秒 | 0.185 秒 |
| 位置の誤差（定常時：中央値 / 95% / 最大） | 0.05 / 0.17 / 0.24 m | 0.05 / 0.19 / 0.26 m |
| 向き（ヨー）の誤差（中央値 / 95%） | 0.2° / 1.4° | 0.2° / 1.2° |
| 参加・再接続直後 1.5 秒の最大誤差 | 0.65 m | 1.68 m（再接続の直後） |
| RTT（平均 / 最大） | 17 / 75 ms | 17 / 50 ms |
| 所有権の確認（自分＝シミュレーションあり・一人称あり、相手＝`Remote`・停止・一人称なし） | 56 回、違反 0 | 48 回、違反 0 |
| エラー / 警告 | 0 / 0 | 0 / 0 |

- 接続・切断：Host は Client の接続 2 回（最初と再接続）・切断 2 回を記録し、プレイヤー数は 2 → 1 → 2。Client は再接続で新しい ID（1 → 2）の体が出現した。
- スクリーンショットで、両方の画面に相手の全身（銃を持ち、走り・ジャンプのアニメーション）が見えることを確認。
- PlayMode テスト：Editor 内で Host を開始 → 自分の体を所有・入力は `PlayerInputReader`・`CharacterCommands` で移動・ピッチ送信 → Leave でロビーカメラに戻る。コピーの見せ方（入力・カメラ・シミュレーションなし、全身表示、ローカルの人間と誤認しない）。

### 7.3 残っている問題（ブラッシュアップ・Phase 6 へ）

| 問題 | 内容 | 対応案 |
|---|---|---|
| キャラ選択が同期されない | `PlayerCharacterSwap` は起動した端末の選択（`-character`）で体を差し替えるので、ウサギで参加した人も相手の画面ではその端末の選択（例：キツネ）で見える | キャラ ID を `NetworkVariable` で送り、コピーは受け取った ID で体を差し替える（差し替えを Awake から出現時に移す） |
| 参加直後の追いつき | 出現から約 1.5 秒、補間が追いつくまで最大 0.65〜1.7 m ずれ、一瞬速く動いて見える | 出現直後はスナップ（補間なし）にする、または時刻同期が落ち着くまで非表示 |
| 表示の遅れ 0.19 秒 | Netcode の既定の補間バッファ。協力 PvE なら許容範囲 | 補間の設定を詰める。Phase 6 のホスト権威化で再計測 |
| 戦闘は未同期 | 射撃・スキル・デッキ・HP・敵・NPC は同期しない。コピーは `CombatantRegistry` に載らないので、敵・NPC・HUD からは見えない | Phase 6（§3 の権限表どおりホスト権威） |
| Net_Smoke に HUD がない | 左上の簡易パネルだけ | 本番のシーンに組み込むときに HUD を `FindLocalHuman` 前提から複数人対応へ |
| 未検証 | 別の PC 同士（LAN）、メイン PC と Ally X、人の手での操作、Multiplayer Play Mode | 手で試す方法（上記）で確認 |

## 8. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| ヒットスキャンの遅延補償 | 撃ったのに当たらない感覚 | ホスト側で発砲時刻に合わせた巻き戻し判定（ラグ補償）を Phase 6 で検討 |
| クライアント予測の補正 | 移動のガタつき | まず所有者権威で開始し、照合導入時にスムージングを入れる |
| デッキ状態の不一致 | 手札表示がずれる | ホストを正本にし、シード＋操作列で決定性を保証。差分にシーケンス番号を付ける |
| コンボの重複発動 | 二重ダメージ | 判定はホストのみ。クライアントは結果を受信するだけ |
| 演出の帯域 | 派手なコンボでパケット増加 | エフェクトは ID のみ送信、ローカル再生 |
| NPC 置き換え時の状態引き継ぎ | 途中参加で不整合 | 置き換え手順を状態機械として設計し、テストを用意 |
| 有料サービス | Relay / Lobby の利用量 | 無料枠・料金を事前に確認し、ユーザーの承認を得てから有効化 |
| バージョン依存 | NGO と Unity の組み合わせ | 2026-11-08 に 6000.5.4f1 で NGO 2.13.3 を導入（更新は保留中）。6000.6.8f1 へ更新するときに NGO の版と Net_Smoke の無人テストを再確認する |
