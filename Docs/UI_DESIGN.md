# UI_DESIGN — 世界観に合わせた UI（灯守隊の探索端末）

2026-11-08 ユーザー指示による UI 全面改修の設計書。全 7 フェーズのうち **Phase 1（共通デザインシステム）と Phase 2（戦闘 HUD・スキルカード 3 枚）を実装済み**。
コードは `Assets/_Game/Scripts/UI`（共通部品は `UI/Theme`、戦闘 HUD の部品は `UI/Combat`）。

## 2. デザイン方針とトークン（`UiTokens`）

コンセプト：**古代文明の工業技術 × 原脈ホログラム × スタイライズド SF ファンタジー**。
厚みのある金属フレーム（面取り・ベベル・控えめな継ぎ目とリベット）、琥珀色の操作ランプ、青白い原脈の回路模様（パネル内に 5% の濃さ）、属性ごとの発光色。
暗すぎるサイバーパンク・無機質な軍事 HUD・派手なネオン・ガラス表現はしない。

| トークン | 値 | 用途 |
|---|---|---|
| `Background` | `#151E2B` | 最も暗い面（キーの台座、通知の地） |
| `Panel` | `#293848`（不透明度 0.94） | パネル |
| `PanelDeep` | `#1B2634` | カードの地 |
| `TextMain` | `#F3F0E8` | メイン文字 |
| `TextSub` | `#A7B8C7` | 補助文字 |
| `Accent` | `#E8AC54` | 強調・琥珀ランプ・フォーカス |
| `FrameSteel` / `FrameLight` / `FrameDark` | `#6A7C8E` / `#9DB0C2` / `#0D141D` | 金属フレーム・縁 |
| `Energy` | `#CDEEFF` | 原脈の回路・蘇生・回避ランプ |
| `Fire` / `Ice` / `Lightning` / `Gravity` | `#F77B40` / `#9BDEFF` / `#59D7F1` / `#AC86EF` | 属性（UI） |
| `Neutral` | `#D8CCB2` | 無属性（どの属性にも見えない石色） |
| `Common` / `Rare` / `Epic` / `Legendary` | `#B9C3CD` / `#5FD39B` / `#E97FB4` / `#FFD466` | レアリティ（属性色と色相を 18° 以上離す） |
| `SyncGold` | `#F6C85F` | 原脈同調の金枠・同調マーク |
| `Health` / `Shield` | `#8EDB8A` / `#DDF3FF` | HP / 障壁 |
| `Danger` / `DangerText` | `#FF5A4A` / `#FF9A8C` | 危険（バー・ランプ）／危険の文字 |

- **文字のコントラスト**：メイン・補助・強調・危険の文字は、パネルの後ろが白・黒・空・砂のどれでも 4.5:1 以上（EditMode テストで保証）。属性名・レアリティ名・同調の金もカード上で 4.5:1 以上。属性色そのものを小さい文字に使わず、`ElementText`（属性色＋メイン文字 30%）を使う。
- **色だけに頼らない**：属性はアイコンの形（炎・雪の結晶・稲妻・軌道・菱形）でも区別できる（形の重なりが 50% 未満をテストで保証）。氷と雷は色が近いので形と名前で見分ける。レアリティは ◆ の数（1〜4）、フォーカスは四隅の括弧で示す。
- 雷の UI 色（シアン）はエフェクトの雷（黄、`Palette.Lightning`）と異なる。UI はキャラクター（雷ウサギの青白い発光）に合わせた。
- 文字サイズ（1920×1080 基準、コンパクト版）：Caption 15 / Body 16 / Label 17 / Title 20 / Heading 24 / Display 30 / 残弾 40。戦闘 HUD の最小は 15（720p で 10 px、Ally X の 1080p で 15 px）。HUD の文字は縁取りつき。フォントは OS の Yu Gothic UI（TextMeshPro は未使用、§8）。

| 部品 | 内容 |
|---|---|
| `UiSprites` | 外部素材なしでコード描画するスプライト：面取りパネルの地と金属フレーム（3 種、9 スライス、ベベル・継ぎ目・リベット）、回路模様（タイル）、発光、ランプ、菱形、同調マーク、六角ソケット、グラデーション、属性アイコン 5 種、障壁・上下矢印・十字。初回使用時に数 ms で生成してキャッシュ |
| `UiWidgets` | パネル（地＋模様＋フレーム）、ラベル（影つき）、アイコン、ランプ（`LampView`）、バー（`HudBar`：減少時に残像と発光）、キー表示、フォーカス括弧、状態チップ |
| `SkillSlotView` / `CardViewData` | 戦闘 HUD の小さなスキル枠（§4.1） |
| `CardFrameView` | 大きい共通カードフレーム（§4.2）。報酬・交換・図鑑で使う予定 |
| `TerminalButton` | 共通ボタン：押下で琥珀ランプが点灯、フォーカス中は四隅の括弧（マウス・コントローラー両方）。何もしないボタンは押せない状態で作る |
| `HudNotifications` / `NotificationFeedView` | 戦闘通知の受け口と表示（左下の戦闘ログ、最大 5 行、約 4 秒）。種類：情報・目標・成功・警告・危険・協力・蘇生 |
| `InputGlyphs` | 今使っている入力機器（キーボード・マウス／コントローラー）を判定し、キー表示を切り替える。Ally X（Handheld ティア）はコントローラー表示で始まる |

| `HudSafeFrame` | HUD を 16:9 の枠に収める（ウルトラワイドで HP・武器が画面端へ離れない） |
| `UiStyleGallery` | F8（Editor・開発ビルドのみ）：共通部品と未実装の状態の見本。「見た目の確認用（操作できません）」と明記 |
| `WorldTerms` | 仮の固有名詞（§1） |

キャンバスは `HudKit.CreateCanvas`：CanvasScaler を 1920×1080 から **Expand** で拡大縮小するので、どの比率でも基準の配置が全部見える（720p は 1080p の縮小、16:10 は上下に余白、ウルトラワイドは左右に余白）。

## 4. スキルの表示

### 4.1 戦闘 HUD のスキル枠（`SkillSlotView`、下中央）

76×76 の正方形＋下にキー表示。表示：カードのアイコン、属性色の細い枠（レジェンダリーは金）、残り回数（左上。1 回で琥珀、0 で赤）、レアリティ（右上の小さな ◆ 1〜4）、ゲージ（下端の細いバー、使用回数の区切り線、減ると残像と発光）、CD（上からの影と残り秒）、強化（右下の「+N」、変異は「変」）、操作キー（今の機器のもの）、アイテム対象（琥珀の四隅括弧と上の「▼」）。
スキル名と説明は枠に出さず、**カードを引いたときに下中央へ 2 秒ほど**（アイコン・名前・説明 1 行）表示する（開幕の 3 枚は出さない）。

**原脈同調（特化スキル）**：金の枠、上辺中央の同調マーク、ゆっくり脈動する発光。ゲージ 0 でも枠は残り「使用不可」を表示する。
→ **ゲーム側の特化の仕組みはまだ無い**ので、戦闘中の手札は常に通常表示（`CardViewData.Specialized = false`）。見た目は F8 のプレビューで確認できる。ゲージの回復方法も未確定のため、新しい仕様は入れていない。

切り替え：使い切った枠は下へ沈んで消え（0.22 秒）、引いたカードは左から滑り込む（0.26 秒）。

### 4.2 共通カードフレーム（`CardFrameView`）

220×168 の大きいカード。名前・属性・レアリティ・ゲージ・消費・回数・CD・キー・強化・変異・同調を全部表示する。戦闘 HUD では使わず、報酬選択・交換・図鑑（Phase 3〜5）で使う予定。F8 のプレビューで確認できる。

## 5. 戦闘 HUD の配置（`HudLayout`、1920×1080 の枠、原点は左下）

2026-11-08 のユーザーの指摘「UI が大きすぎる」を受けて**コンパクトに作り直した**（参考画像の「小さく・パネル少なめ」という方向性だけを取り入れ、他作品の UI そのものは真似ていない）。同日、ユーザーがこの大きさ・配置で進めることを承認。
常に出ている領域の合計は画面の約 6%（以前は約 20%）。EditMode テストで 8% 未満を保証している。パネルは目標の枠だけで、ほかは縁取りした文字と、後ろの薄い暗がり（ぼかした影）で読ませる。

| 場所 | 領域 | 内容 |
|---|---|---|
| 左下 | `Vitals` (24,24) 420×60 | HP バー（数値はバーの中、25 ごとの区切り・被弾の残像・30% 以下で赤く点滅）、その上に障壁の細い線。上の行に属性マーク・名前・状態アイコン最大 3（障壁・攻撃強化・脆弱・継続ダメージ・属性、残り秒）・回避のランプ |
| その上 | `Log` 5 行 | 戦闘ログ：WAVE 開始・突破、味方のダウン・蘇生・後退、あなたの蘇生、NPC の知らせ。新しいものが下、約 4 秒で消える |
| その上 | `Squad` 300×46 | 味方の 1 行：属性マーク・名前・方針と切替キー（ダウン中は「ダウン 18s」「蘇生中 45%」）、細い HP バーと蘇生の進み。味方が増えたら上へ 54 ずつ積む（最大 3 人） |
| 下中央 | `SkillSlot` 3 つ | スキル枠（§4.1）。照準の真下に中央揃え。2026-11-09 のユーザーの指示で右下から移した（右下は一人称の銃が角の外へ抜ける場所で、枠が機関部に重なっていた） |
| その左 | `ItemSlot`・`Piles` | 支援品の枠（アイコン・所持数・使用キー、種類の数だけ小さな ◆、切り替えると名前と効果を知らせる）、山札・捨て札の枚数 |
| 右下の角 | `Weapon` 300×80 | 武器名（属性武器は属性アイコン）、予備（∞＝リロードは常に可能）、残弾（大）／弾倉、残弾のバー（リロード中は琥珀で進み、ランプ点滅）、残弾わずか・弾切れの表示。固有能力のある武器（サンダーホップの帯電連射）は上に 12 分割のゲージ |
| スキル枠の上 | `DeckNotice`・`DrawToast` | 引いたカードの名前と説明（2 秒）、知らせ（クールダウン・アイテム使用・切替・再シャッフル） |
| 右上 | `Objective` 380×82 | 「目標」と WAVE 番号、目標（残りの敵・次のウェーブまで）、現在のエリア |
| 照準の上 | `ComboBanner` | コンボ名、段階、協力ボーナス、参加者、2 つの属性アイコンが共鳴（脈動して寄る） |
| 左上 | `Perf`・`GuideChip` | F3 性能表示、「F1 操作ガイド」（パッドは「Start 操作ガイド（ポーズ）」） |
| 中央 | `CrosshairClear` 400×300 | **何も置かない**（照準と敵のマーカーだけ） |

- 操作ガイドは戦闘中は畳んでおき（F1 で左端に一覧）、ポーズ画面に全操作（キーボード・パッドの 2 列、使っている方を強調）を出す。以前は画面上部に 4 行の説明が常に出ていて、性能表示と重なっていた。
- ポーズ画面は手札・味方の HUD より上、NPC デッキ編集（30）より下の専用キャンバス（25）。
- 被弾の赤い周辺減光は画面全体、敵頭上のマーカーと味方の名札は全画面のキャンバス、それ以外は 16:9 の枠の中。

## 6. 既存機能との接続

UI はゲームの状態を読むだけで、ゲームロジックを二重に持たない。

| 表示 | 読むもの |
|---|---|
| 手札・山札・捨て札 | `DeckController`（`DeckRebuilt`・`Notice`・`SelectedSlot`）、`DeckState`（`CardDrawn`・`CardUsed`・`CardDepleted`・`Reshuffled`、`CardRuntime` の値） |
| 支援品 | `GaugeItemInventory` |
| HP・障壁・状態異常・回避 | `Health`、`CombatStatus`（`StatusEffectsModel`・`ElementAuraModel`）、`FpsMotor.DashCharge` |
| 属性マーク（左下） | 使っているキャラクターの定義（`PlayerCharacterSwap.Current` → `CharacterDefinition.Element`：キツネ＝火、ウサギ＝雷）。定義が無いときだけ `HudController.characterElement`（火） |
| 武器 | `HitscanWeapon.State`（`WeaponState`）、`WeaponDefinition` |
| 目標・WAVE | `WaveDirector.Schedule`（`WaveSchedule`） |
| 隊員 | `NpcController`（判断・方針・`Notice`・`SkillCast`）、`Revivable`（`Downed`・`RevivedByAlly`・`BledOut`） |
| コンボ | `ComboEvents.Triggered` |
| キー表示 | `InputGlyphs`（デバイスを読むのはラベル選択だけ。操作は従来どおり `ICharacterCommandSource`） |

## 8. 既知の課題・決めること

- **デッキ枚数**：指示書は「デッキ 8 枚固定」だが、現在のプレイヤーの初期デッキは 13 枚（`CARD_SYSTEM.md` §12、NPC は 8 枚）。HUD はどちらでも動く。ゲーム側をどうするかは未決定。
- 特化（原脈同調）・パッシブ効果・報酬・研究・セーブ・ランの集計はゲーム側に無い。UI だけ先に作ると「操作できるように見えて何も起きない」ので、各フェーズでロジックと同時に作る。
- 武器名は武器のデータ（`WeaponDefinition.displayName`）をそのまま出す。ウサギを選んでも武器のデータはキツネと同じ「プロトAR」のため、見た目の SMG と名前が合わない（ウサギ側の武器データ待ち）。
- TextMeshPro は Unity 6 の uGUI に含まれるが未使用（既存はすべて Legacy Text＋OS フォント）。移行するには商用利用できる日本語フォント（例：Noto Sans JP、OFL）の同梱が必要。
- 文字の大きさの設定（UI スケール）は無い。コンパクト版は 720p で最小 10 px になる。設定画面（Phase 5）で UI スケールを追加する。
- コントローラーでの実機操作は未確認（仮想ゲームパッドの自動テストと Ally X でのパッド表示開始のみ確認）。

## 9. 確認方法

- Play モード：戦闘 HUD はそのまま。F1 操作ガイド、F3 性能表示、F8 UI プレビュー（Editor・開発ビルドのみ）、Esc / Start でポーズ画面。
- テスト：EditMode `UiDesignSystemTests` 20 件（色・コントラスト・配置の重なり・HUD の面積 8% 未満・比率・カード表示・通知・キー表示・アイコンの形・9 スライス）、PlayMode `HudPlayModeTests` 2 件（全領域の生成、スキル枠とデッキの連動、使い切りと引いたカードの表示、山札・捨て札、キー表示の切替、通知）。
- 比較スクリーンショット：`Screenshots/UI_Redesign/`（Git 対象外）。`before_*`（改修前）/ `after_*`（最初の改修）/ `compact_*`（コンパクト版）と、左右に並べた `compare_*.png`（`compare_original_vs_compact_1080p.png` が改修前とコンパクト版）。
