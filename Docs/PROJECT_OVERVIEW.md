## 1. ゲームコンセプト

**デッキ構築 × 協力スキルコンボ × 3DローグライクFPS。**

プレイヤーは銃による通常射撃で戦いながら、手札に並ぶ「スキルカード」を使って大技・範囲攻撃・状態異常・支援を発動する。
カードは使うたびにゲージを消費し、使い切ると捨て札へ流れて次のカードが山札から補充される。
「どのカードを使い切り、どのカードを延命させるか」という判断と、仲間（NPC／将来はオンラインプレイヤー）との**属性コンボ**が戦闘の核になる。

| 項目 | 内容 |
|---|---|
| ジャンル | 3DローグライクFPS／デッキ構築／協力スキルコンボ |
| プレイ人数 | ソロ＋NPC協力（初期試作はNPC 1人）、将来は最大4人オンライン協力（人間＋NPCで合計4人） |
| 1ラン | 複数ステージを順に攻略 → ステージクリアごとにカード報酬（3枚から1枚選択） |
| 通常射撃 | スキルとは独立。カードゲージを一切消費しない |
| スキル | 大ダメージ・範囲攻撃・状態異常・特殊能力はすべてスキルカードで発動 |

## 2. ゲームの柱（優先順位順）

開発判断に迷ったときは、この順番を優先する。

| 優先度 | 柱 | 具体的な意味 |
|---|---|---|
| 1 | **デッキ構築の戦略性と奥深さ** | カード循環（ゲージ消費→捨て札→ドロー）、回復アイテムによる延命判断、報酬選択、属性シナジー。詳細は `CARD_SYSTEM.md` |
| 2 | **自然で滑らかなキャラクターモーション** | 一人称の腕・武器と、他者から見える全身モーションを分離して高品質化。詳細は `ANIMATION_GUIDELINES.md` |
| 3 | **スキルコンボのド派手なエフェクト** | 通常／強化／属性コンボ／究極コンボの4段階演出。性能ティアで負荷を調整 |
| 4 | **爽快感のあるFPS操作と射撃** | 自然な加減速、低入力遅延、適切なリコイル、過剰なカメラ揺れの回避、引っかかりにくい移動 |
| 5 | **NPC・オンラインプレイヤーとの協力** | 人間とNPCが共通の `ICombatActor` を使い、協力コンボで威力1.3倍（仮）。詳細は `MULTIPLAYER_PLAN.md` |

## 3. ビジュアル方針

- 目標：**カラフルで視認性の高いトゥーン調3D**。
- 参考：Gunfire Reborn の「色彩の明るさ・敵とエフェクトの読みやすさ」という**方向性のみ**を参考にする。
- 属性ごとに明確な色を割り当てる（例：火＝橙／赤、氷＝水色、雷＝黄／紫、重力＝紫／黒）。
- 敵・味方・エフェクト・地形のコントラストを確保し、派手な演出中でも敵が見えることを優先する。
- Phase 1 は URP Lit の仮マテリアル＋ポストプロセス（Bloom／Tonemapping）で構築し、トゥーンシェーダー（Shader Graph）は Phase 5 で導入する。

### オリジナリティのルール（厳守）

- 既存ゲーム（Gunfire Reborn を含む）の**モデル・キャラクター・デザイン・UI・コード・音声・世界観を複製しない**。
- 名前・シルエット・配色の組み合わせが特定作品を想起させる場合は作り直す。
- キャラクター（イグニス／セラ／ヴォルト）と世界観はすべて独自に制作する。

## 4. 開発環境と対象PC

### エンジン・主要技術

| 分類 | 採用技術 | 備考 |
|---|---|---|
| エンジン | Unity 6（現在 **6000.5.4f1**。**6000.6.8f1** はインストール済みだが、ユーザー指示で更新は保留） | 更新前に必ず Git でチェックポイントを作る |
| レンダリング | Universal Render Pipeline（URP） | Unity 6 URP テンプレートから作成 |
| 言語 | C# | ルート名前空間 `CoopDeck` |
| 入力 | Unity Input System | キーボード＆マウス／ゲームパッド両対応 |
| AI移動 | Unity AI Navigation 2.0.13 | 敵の経路探索（Phase 2 で導入済み）、NPC（Phase 4） |
| IK | Unity Animation Rigging 1.4.1 | 敵の頭のエイム（Phase 2 で導入済み）。左手グリップIK・上半身エイム・足IKは本番モデル導入時 |
| テスト | Unity Test Framework | EditMode／PlayMode |
| Editor操作 | Unity CLI（`unity` コマンド）＋ Pipeline パッケージ（`com.unity.pipeline`、導入済み） | Claude Code から Editor を操作。MCP for Unity（mcp-unity）は本プロジェクトには未導入（必要になったら追加） |
| バージョン管理 | Git / GitHub / Git LFS | `Library/` 等の自動生成物は管理しない |
| ネットワーク（将来） | Netcode for GameObjects、Unity Multiplayer Services（Lobby / Relay） | ホスト権威型。Phase 2.5 で最小通信テスト |

パッケージは「使用中の Unity バージョンに対応した安定版」を Package Manager に解決させて採用する（バージョン番号を推測で固定しない）。

### 対象PC

| PC | 仕様 | 役割 | 品質目標 |
|---|---|---|---|
| メインPC | RTX 4070 搭載 | 高品質な3D制作・VFX制作・ビルド・テスト | 性能ティア `High` |
| サブPC（この開発機） | ASUS ROG Ally X（AMD Ryzen Z1 Extreme／Radeon内蔵GPU、1920×1080 120Hz パネル、Windows） | Claude Code での開発、軽量な Unity 編集、コントローラー操作確認、携帯機性能の実測 | 性能ティア `Handheld`：**内部解像度 900p・低〜中品質・60fps** |

- 両PCで同一プロジェクトを GitHub 経由で共有する。
- Ally X では URP の Render Scale ≈ 0.83（1080p パネル上で内部 900p 相当）＋ FSR アップスケーリング、影の距離・解像度を削減。実測結果に応じて最適化する。
- 性能ティアは起動時に自動判定し、コマンドライン引数で上書き可能にする（`ARCHITECTURE.md` 参照）。
- Windows（x86_64）向けスタンドアロンビルドを作成できる状態を維持する。

## 5. 操作方法

Phase 3（2026-11-07）でスキル枠・アイテム・カード選択をデッキシステムに接続した。

| 操作 | キーボード＆マウス | ゲームパッド | 状態 |
|---|---|---|---|
| 移動 | WASD | 左スティック | 実装・自動テスト済み |
| 視点 | マウス | 右スティック（応答カーブ＋加速） | 実装・自動テスト済み |
| ジャンプ | Space | South（A） | 実装・自動テスト済み |
| スプリント | 左 Shift（押し続け） | 左スティック押し込み（トグル、停止で解除） | 実装・自動テスト済み |
| ダッシュ（短距離回避、2チャージ） | 左 Ctrl | East（B） | 実装・自動テスト済み |
| 射撃 | 左クリック | RT | 実装・自動テスト済み |
| リロード | R | West（X） | 実装・自動テスト済み |
| 性能表示の切替 | F3 | View（Select） | 実装済み |
| スキル枠 1 | Q | LB | 実装・自動テスト済み（実機キー入力も仮想デバイスで検証） |
| スキル枠 2 | E | RB | 同上 |
| スキル枠 3 | F | North（Y） | 同上 |
| カード選択（アイテム対象） | 1 / 2 / 3 | 十字キー ← / → | 同上。最後に使ったカードが自動で選択される |
| アイテム使用 | G | 十字キー↑ | 同上 |
| アイテム切替 | T | 十字キー↓ | 同上 |
| 操作ヒントの表示切替 | F1 | — | 実装済み |
| ポーズ | Esc | Start | カーソル解除など最小限 |

キー割り当ては Input Actions アセットで管理し、将来リバインド UI を追加できる構造にする。

## 6. 想定キャラクター（初期は1体を完成させる）

| キャラクター | 得意属性 | 特徴 |
|---|---|---|
| イグニス | 火 | 高火力・爆発特化 |
| セラ | 氷 | 妨害・支援特化 |
| ヴォルト | 雷 | カード循環・高速戦闘特化 |

- どのキャラクターも基本的に**全属性のカードを使用可能**。固有パッシブ・コンボ補正・移動能力で戦い方を変える。
- キャラクター専用カードを大量に作ることは避ける。
- キャラクター定義（ID、名前、HP、移動能力、固有パッシブ、初期デッキ、得意属性、固有コンボ補正、NPC行動傾向、モデル・Animator設定）は ScriptableObject で管理する。
