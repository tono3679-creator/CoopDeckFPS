# DEVELOPMENT_PLAN — 開発計画

## 0. 進め方の原則

- 巨大なゲームを一度に作らない。**フェーズ単位で「実装 → コンパイル → 自動テスト → 実機確認」を繰り返す。**
- **完了＝検証済み。** コンパイルが通っただけ、コードを書いただけの機能は完了扱いにしない。
- 各タスクの状態：`[ ]` 未着手／`[~]` 作業中／`[x]` 検証済み（完了）。
- 状態の更新は実際に検証したタイミングで行い、`CHANGELOG.md` にも記録する。
- 各フェーズ終了時は、以下6項目を日本語で報告する。
  1. 実装した内容
  2. 作成・変更した主なファイル
  3. 動作確認の結果
  4. 残っている問題
  5. 次に実装すべき内容
  6. Unity 上でユーザーが操作する必要があること

### 共通の完了条件（全フェーズ）

| 条件 | 確認方法 |
|---|---|
| コンパイルエラー・警告の増加なし | Unity のバッチモード起動ログ、または `unity status` / Console |
| 自動テストが通る | Test Runner（EditMode／PlayMode）、バッチモード `-runTests` |
| 実際に動く | サンドボックスシーンでの Play モード確認、必要に応じてスクリーンショット |
| ドキュメント更新 | 該当 `Docs/*.md` と `CHANGELOG.md` |
| Git にコミット | 意味のある単位でコミット（自動生成物を含めない） |

## ROG Ally X 性能計測手順

### 準備

1. Ally X を AC 電源に接続し、Armoury Crate の動作モードを記録する（例：Performance 25W / Turbo 30W）。
2. Windows ビルド（Development Build ではない通常ビルド）を使う。Editor 上の計測は参考値扱い。
3. 性能ティアが `Handheld` になっていることを確認する（自動判定、またはコマンドライン引数で指定）。

### 計測

1. サンドボックスシーンを起動し、**F3** でフレームタイム表示を有効にする。
2. 以下の3パターンをそれぞれ 60 秒間行う。
   - A：静止（シーン中央で正面を向く）
   - B：移動＋視点操作（コースを一周）
   - C：連続射撃（的に向けて弾倉を撃ち切る → リロードを繰り返す）
3. 表示される **平均 FPS** と **1% Low**、平均フレームタイム（ms）を記録する。
4. 気になる場面はスクリーンショットを撮り、`Docs/` からリンクする。

### 無人計測（推奨・再現性あり）

```
Builds\Windows\CoopDeckFPS.exe -perfrun 30 -perfout PerfCaptures\perf.json            # 自動判定ティア、60fps 上限
Builds\Windows\CoopDeckFPS.exe -perfrun 30 -perfout PerfCaptures\perf.json -uncapped  # 余力の計測
Builds\Windows\CoopDeckFPS.exe -perfrun 30 -perfout PerfCaptures\perf.json -tier high -uncapped
```

```
Builds\Windows\CoopDeckFPS.exe -perfrun 30 -perfout PerfCaptures\arena.json -perfarena  # 敵アリーナでの戦闘（Phase 2〜）
```

3 秒待機後に 30 秒計測。既定は自動操縦（射撃場を左右に見回しながら連射、反動制御あり、的の撃破エフェクトも発生）＝パターン C 相当。`-perfidle` で静止（パターン A）。
`-perfarena` はプレイヤーをアリーナに置いてウェーブを開始し、自動操縦が最寄りの敵の胸を狙って撃つ（スキルも 2.2 秒ごと）。計測中はプレイヤーが倒れないよう HP を大きくする。JSON に到達ウェーブ（`waveReached`）と最大同時敵数（`maxEnemiesAlive`）が入る。

**所見**：Phase 1 のテストシーンでは Ally X で 60fps を安定維持し、上限なしで約 1.6 倍の余力がある。シーンが軽いため GPU 設定の差はまだ小さい。Phase 2 の敵アリーナ（NavMesh・アニメーション・Animation Rigging・敵弾を含む最大 6 体）でも 60fps 上限では 1% Low 58 以上を維持し、上限なしの平均は Phase 3 とほぼ同じ（約 91fps）。敵・VFX がさらに増える Phase 4〜5 で再計測し、CPU（スクリプト・物理・描画コマンド）と GPU のどちらが律速かを Profiler で確認する。

### 判定と対応

- 平均 60fps 未満、または 1% Low が 45fps 未満なら、以下の順に調整して再計測する。
  1. 影（距離・解像度・カスケード数）
  2. Render Scale（0.83 → 0.75）
  3. ポストプロセス（Bloom の品質）
  4. エフェクトの粒子数倍率
  5. ライト数・追加ライトの影
- 調整内容と結果は記録表に追記し、`ARCHITECTURE.md` の性能ティア設定も更新する。
