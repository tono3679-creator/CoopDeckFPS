# CARD_SYSTEM — デッキ構築・カード循環・コンボ

> このゲームで**最も重要なシステム**。実装は Phase 3（デッキ）と Phase 4（コンボ）。
> 本ドキュメントは仕様の正本とし、変更時は必ず更新する。

---

## 1. 基本ルール

| # | ルール | 値・補足 |
|---|---|---|
| R1 | 初期デッキ | **12枚**（アクティブカードのみ） |
| R2 | 同時使用可能なカード（手札枠） | **3枠**（NPC は2枠） |
| R3 | ゲージ | カードごとに**独立**したゲージを持つ |
| R4 | 標準ゲージ最大値 | **100**（カード定義・強化・パッシブで変化しうる） |
| R5 | 発動 | スキル発動でそのカードのゲージを消費 |
| R6 | 最後の1回 | 残りゲージが消費量未満でも、**最後の1回は通常威力で発動**でき、ゲージは0になる |
| R7 | 自動捨て札 | ゲージが0になったカードは**自動で捨て札へ**移動 |
| R8 | ドロー | 空いた枠に山札から次のカードを**1枚ドロー** |
| R9 | リシャッフル | 山札が0なら捨て札をシャッフルして山札にする |
| R10 | ゲージ回復 | 再び引いたカードのゲージは**最大値まで回復** |
| R11 | 任意破棄 | **禁止**。使い切るまで別のカードと交換できない |
| R12 | 通常射撃 | カードゲージを**消費しない** |
| R13 | 共有エネルギー | **導入しない**（ゲージはカード単位のみ） |
| R14 | パッシブカード | 山札に入れず、ドロー対象にしない。獲得したラン中ずっと効果が続く |

### 発動可否

- ゲージが **1以上** あれば発動可能（R6 による）。
- ゲージが 0 のカードは手札に存在しない（R7 で即座に捨て札へ移る）。
- スキルごとのクールダウン（連打防止）は `CardDefinition` に任意で設定できる。ゲージとは別の概念。

## 3. カードの種類

### アクティブカード（手札に表示され、戦闘中に使う）

| 例 | 属性 | 役割 |
|---|---|---|
| 氷の槍 | 氷 | 単体ダメージ＋凍結付与 |
| 連鎖雷撃 | 雷 | 連鎖ダメージ＋帯電付与 |
| 火炎旋風 | 火 | 範囲ダメージ＋炎上付与 |
| 重力崩壊 | 重力 | 吸引＋重力付与 |
| メテオストライク | 火 | 遅延大範囲ダメージ |
| シールド | なし | 自分／味方にシールド |
| 範囲回復 | なし | 範囲内の味方を回復 |
| 敵のマーキング | なし | 被ダメージ増加デバフ |

### パッシブカード（獲得時からラン中ずっと有効、山札に入らない）

| 例 | 効果の種類 |
|---|---|
| ゲージ消費量 15% 減少 | 消費量の修正 |
| カードを使い切ると追加爆発 | `CardDepleted` イベントへのフック |
| 協力コンボ成功でゲージ回復 | `ComboTriggered` イベントへのフック |
| 状態異常の持続時間延長 | 状態異常の修正 |
| スキルダメージ増加 | ダメージ計算の修正 |

パッシブは「**修正値（Modifier）**」または「**イベントフック**」のどちらかで表現し、コードを増やさずにデータで追加できるようにする（§7）。

## 4. データモデル

カード定義（不変・共有）とカードインスタンス（ランタイム・個別）を分離する。**同じ種類のカードを複数枚所持できる**のはこの分離による。

### 4.1 `CardDefinition`（ScriptableObject）

| フィールド | 型（予定） | 説明 |
|---|---|---|
| `id` | `string` | 不変の一意ID（例：`card.chain_lightning`）。セーブ・通信で使う |
| `displayName` | `string`（将来ローカライズキー） | 表示名 |
| `description` | `string` | 説明文（数値は `{damage}` などのプレースホルダで差し込み） |
| `type` | `CardType`（`Active` / `Passive`） | 種類 |
| `element` | `Element`（`None` / `Fire` / `Ice` / `Lightning` / `Gravity`） | 属性 |
| `rarity` | `CardRarity`（`Common` / `Rare` / `Epic` / `Legendary` 予定） | 報酬の出現率に影響 |
| `maxGauge` | `int` | ゲージ最大値（標準100） |
| `gaugeCost` | `int` | 1回の消費量 |
| `cooldown` | `float` | 連打防止（秒、任意） |
| `targeting` | `CardTargeting`（`Self` / `Aim` / `AimPoint` / `AreaAroundSelf` / `Ally`） | 照準方式 |
| `effects` | `SkillEffectDefinition[]` | 効果（ダメージ、状態異常付与、回復、シールド、吸引など）を順に適用 |
| `vfx` | 段階別 Prefab 参照 | `Normal` / `Upgraded` / `Combo` / `Ultimate` |
| `upgrades` | `CardUpgradeStep[]` | 強化段階ごとの修正値 |
| `passiveModifiers` | `ModifierDefinition[]` | パッシブカードの効果（`type == Passive` のとき） |
| `tags` | `string[]` | シナジー判定用（例：`explosive`, `chain`） |

### 4.2 `CardInstance`（ランタイム、純 C#）

| フィールド | 説明 |
|---|---|
| `instanceId` | ラン内で一意な整数ID（通信同期・UI追跡用） |
| `definition` | 参照する `CardDefinition` |
| `currentGauge` | 現在ゲージ |
| `upgradeLevel` | 強化段階（0 = 未強化） |
| `modifiers` | このインスタンスに付いた修正（変異、消費量変化、最大値変化など） |
| `EffectiveMaxGauge` / `EffectiveCost` | 定義＋強化＋インスタンス修正＋パッシブを合成した値（計算プロパティ） |

### 4.3 `DeckState`（純 C#、MonoBehaviour にしない）

```
DeckState
 ├─ DrawPile      : List<CardInstance>   山札（先頭が次に引くカード）
 ├─ ActiveHand    : CardInstance?[N]     手札（固定枠。プレイヤー3、NPC 2）
 ├─ DiscardPile   : List<CardInstance>   捨て札
 ├─ Passives      : List<CardInstance>   パッシブ（ドロー対象外）
 └─ Random        : IRandom              シード付き乱数（注入）
```

- **MonoBehaviour にしない理由**：EditMode テストで規則を完全に検証でき、ホスト側で状態を持って通信同期しやすく、NPC とプレイヤーで同じコードを使えるため。
- 表示（UI）や発動（スキル実行）は `DeckState` のイベントを購読する別コンポーネントが担当する。
- 乱数は `IRandom`（シード指定可能）を注入する。**同じシードと同じ操作列なら同じ結果**になり、ネットワーク同期・リプレイ・バグ再現に使える。

### 4.4 操作（API）

| 操作 | 説明 | 主な規則 |
|---|---|---|
| `DrawCard(slot)` | 指定の空き枠に1枚引く | 山札0なら `Reshuffle()` を先に行う。引いたカードのゲージを最大値に回復（R10） |
| `UseCard(slot)` | 枠のカードを発動 | ゲージ ≥ 1 で発動可。消費後のゲージは `max(0, gauge - cost)`。0になったら `DiscardOnEmpty(slot)` |
| `DiscardOnEmpty(slot)` | ゲージ0のカードを捨て札へ移し、空き枠にドロー | 外部から任意破棄には使えない（ゲージ > 0 なら拒否）（R11） |
| `Reshuffle()` | 捨て札を山札に戻してシャッフル | 山札が空のときのみ自動で呼ばれる |
| `AddCard(def)` | 新しいインスタンスを山札（または捨て札）に追加 | 追加先は報酬仕様で決める（初期案：捨て札に追加し、次のリシャッフルで混ざる） |
| `RemoveCard(instanceId)` | カードをデッキから取り除く | ショップ・イベント用。手札にある場合は §6 参照 |
| `UpgradeCard(instanceId)` | 強化段階を上げる | 強化で最大値が増えた場合、現在ゲージの扱いは §6 参照 |
| `RestoreCharge(slot, amount)` | ゲージを回復 | 上限超過禁止、捨て札は対象外、ゲージ0では使えない（§5） |

`UseCard` は「発動できたか」と「発動時の情報（カード、威力段階、消費前後のゲージ）」を返し、実際のスキル実行は呼び出し側が行う。

### 4.5 イベント

| イベント | 発火タイミング | 主な購読者 |
|---|---|---|
| `CardDrawn(slot, card)` | 枠にカードが入った | 手札UI、ドロー演出 |
| `CardUsed(slot, card, gaugeBefore, gaugeAfter)` | 発動した | スキル実行、UI、パッシブ |
| `GaugeChanged(slot, card, oldValue, newValue)` | ゲージが変化（消費・回復） | UI |
| `CardDepleted(slot, card)` | ゲージが0になり捨て札へ移った | パッシブ（使い切り時の追加爆発など）、UI |
| `Reshuffled(count)` | 捨て札を山札に戻した | UI、SE |

イベントの発火順序は固定する（例：`CardUsed` → `GaugeChanged` → `CardDepleted` → `Reshuffled`（必要時） → `CardDrawn`）。

## 5. ゲージ回復アイテム

| アイテム | 効果 | 対象選択 |
|---|---|---|
| チャージポーション | **選択した手札1枚**のゲージを **+40** | 手札の枠を選ぶ |
| 共鳴結晶 | **手札3枚**のゲージをそれぞれ **+25** | 不要（手札全体） |

### ルール

- ゲージ上限を**超える回復は禁止**（超過分は切り捨て）。
- **捨て札のカードには使用不可**（そもそも手札のみが対象）。
- ゲージが **0 になる前に使用する必要がある**（0 で即捨て札に移るため、0 のカードは対象にならない）。
- 所持上限は**初期2個**（アイテム種類ごとの上限か合計上限かは Phase 3 で決定。初期案：種類ごと）。
- 使用すると所持数が減る。上限は将来パッシブで増やせる。
- 対象が既に最大値のときは「使用不可」とし、アイテムを消費しない。

### 戦略上のトレードオフ（重視する点）

回復は強力なカードを**手札に長く留められる**一方、そのカードが捨て札に行かないため**次のカードを引くタイミングが遅れる**。
- 例：強い「メテオストライク」を延命する ↔ 山札にある協力コンボ用の雷カードを早く引きたい。
- 手札3枠のうち1枠を延命すると、残り2枠の回転だけで山札を回すことになる。
- UI では「延命するとあと何回使えるか」と「山札の残り枚数」を同時に見せ、判断を支援する。

### 入力（暫定）

- アイテム使用：G／十字キー上。チャージポーションは「使用ボタン → 対象枠のスキルボタン」で枠を選ぶ案を Phase 3 で検証する。
- アイテム切替：T／十字キー右。

## 6. エッジケース

| ケース | 扱い |
|---|---|
| デッキ枚数が手札枠数より少ない（例：2枚で3枠） | 引ける分だけ入れ、残りの枠は空のまま。空き枠は次のドロー機会（他のカードが捨て札に移ったとき）に補充を試みる |
| 全カードが手札にあり山札も捨て札も0 | ドロー不可。枠は空のまま（エラーにしない） |
| 山札0・捨て札1枚で、そのカードが今捨てられた | リシャッフル → 同じカードを再ドロー（ゲージ全回復）。仕様どおりとする |
| アイテムを「次の1回で0になる」カードに使う | 使用可（ゲージ > 0 のため）。回復後の値で次回消費を計算 |
| 発動とアイテム使用が同フレーム | ホスト側で入力順に処理。順序は `DeckState` への呼び出し順で決まる |
| 手札にあるカードを `RemoveCard` | 枠を空けて、その枠にドローを試みる（捨て札には入れない） |
| 山札・捨て札にあるカードを `RemoveCard` | そのリストから取り除くだけ |
| 強化で `maxGauge` が増えた | 手札にある場合：現在ゲージは維持（増えた分は回復しない）。次にドローしたとき新しい最大値まで回復 |
| 強化で `maxGauge` が減った | 現在ゲージを新しい最大値に切り詰める（0にはしない） |
| 消費量修正で `cost` が 0 以下 | 最低1に制限（無限発動を防ぐ） |
| パッシブカードを `AddCard` | `Passives` に入り、山札には入らない |
| NPC デッキ | 8枚・2枠。規則は完全に同じ（同じ `DeckState` を使う） |

## 7. デッキの成長とデータ駆動設計

### 報酬フロー（Phase 3 で実装）

1. ステージクリア
2. 報酬候補 **3枚**を提示（レア度・キャラクターの得意属性・既存デッキのシナジーで重み付け抽選、乱数は `IRandom`）
3. 1枚を選択（スキップの可否は Phase 3 で決定）
4. `AddCard` で追加 → `CHANGELOG` に残す必要はないが、ランのログには記録

### 将来の成長要素

| 要素 | 実現方法 |
|---|---|
| カード追加 | `AddCard` |
| カード削除 | `RemoveCard`（ショップ／イベント） |
| カード強化 | `UpgradeCard` → `CardUpgradeStep` の修正値を適用 |
| カード変異 | 別 `CardDefinition` への差し替え、または変異 Modifier |
| レア度 | `CardRarity` と報酬テーブル |
| 属性シナジー | `tags` と `element` を条件にした Modifier（例：火カード3枚以上で火ダメージ+10%） |
| 消費量の変化 | `ModifierDefinition`（対象 = `GaugeCost`、加算／乗算） |
| ゲージ最大値の変化 | `ModifierDefinition`（対象 = `MaxGauge`） |

### 修正値（Modifier）の考え方

- `ModifierDefinition`：`target`（`GaugeCost` / `MaxGauge` / `SkillDamage` / `StatusDuration` …）、`operation`（`Add` / `Multiply`）、`value`、`condition`（属性・タグ・カードID）。
- 適用順は「定義値 → 強化 → インスタンス修正 → パッシブ（加算 → 乗算）」で固定する。
- **新しいカードの追加は「`CardDefinition` アセットの作成＋既存の `SkillEffectDefinition` の組み合わせ」で済むことを目標**とし、新しい効果の種類が必要なときだけコードを追加する。

## 8. 属性・状態異常・コンボ（Phase 4）

### 属性

`Fire`（火）／`Ice`（氷）／`Lightning`（雷）／`Gravity`（重力）

### 初期コンボ

| コンボ | 条件 | 効果 |
|---|---|---|
| 超伝導バースト（氷＋雷） | 凍結した敵への雷撃 | 周囲の敵に連鎖ダメージ |
| 灼熱特異点（火＋重力） | 火と重力の組み合わせ | 敵を中心に吸引＋炎の範囲ダメージ |
| オーバーロード（火＋雷） | 火と雷の組み合わせ | 大規模な属性爆発＋周囲に追加ダメージ |

### 判定ルール

- 対象ごとに「付与された属性状態」を **付与時刻（timestamp）と付与した行動者（actor）** つきで保持する。
- `ComboRule`（データ）：「属性Aが付与されている対象に、**4秒以内**に属性Bが命中」→ コンボ発動。
- **同じ敵**に対して判定する。
- **異なるプレイヤー・NPC 間**でも、**自分自身のカード組み合わせ**でも発動可能。
- 付与者と命中者が異なる場合は**協力コンボ**として威力 **1.3倍**（仮値、`ComboRule` に設定）。
- 同一対象への同一反応には **3秒の再発動制限**（対象×反応ごとのクールダウン）。

### 無限連鎖の防止

1. コンボで発生したダメージは `DamageInfo` に `IsComboDamage` フラグを持ち、**新たなコンボを起こさない**（連鎖深さの上限 = 1）。
2. 対象×反応ごとの再発動制限 3秒。
3. 第2の安全網として、**対象ごと・フレームごとのダメージ上限（ダメージバジェット）**を設け、異常な多重ヒットを打ち切る。
4. 連鎖ダメージ（超伝導バーストなど）は「1回の発動で最大何体まで」を `ComboRule` に設定する。

### ダメージと演出の分離

- 処理順：**ダメージ解決 → イベント発行 → 演出再生**。
- `ComboRule` は VFX Prefab を参照するだけで、エフェクトの差し替えがダメージ処理に影響しない。
- コンボ判定は `CombatEvents`（ダメージ適用イベント）を購読して行う。オンラインでは**ホストだけ**が判定する（`MULTIPLAYER_PLAN.md`）。

## 9. NPC デッキ

| 項目 | プレイヤー | NPC |
|---|---|---|
| 初期デッキ | 12枚 | **8枚** |
| 手札枠 | 3 | **2** |
| 規則 | §1 | **同じ**（同じ `DeckState` クラス） |
| 発動判断 | 入力 | AI（State Machine / Utility AI）がスキル枠ボタンに相当するコマンドを出す |

NPC はプレイヤーと同じ `CharacterCommands`（スキル枠の押下を含む）を出力し、同じ経路でカードを使う。これにより、将来オンラインプレイヤーが NPC 枠を置き換えられる。
